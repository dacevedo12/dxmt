# test_map_synchronisation, the two cases that expect an UNSYNCHRONISED map.
# D3D9 permits a driver to hand the application a pointer into the memory a
# queued draw is reading, so a write issued after that draw was recorded can
# still reach it. DXMT never does: Lock returns a host mirror and the device
# allocation is a cache the consuming draw refreshes, so such a write cannot
# reach a recorded draw and the map is always synchronised.
#
# The mirror is not a convenience. Registering guest pages for the GPU to read
# livelocks under Rosetta, and on a 32-bit guest every registered allocation
# spends address space the process does not have, so the storage model is forced
# rather than chosen. Direct3D's own WARP renderer reports synchronised here as
# well and Wine marks the case broken() for it, so no shipped application can
# depend on the behaviour this asserts. The divergence also runs in the safe
# direction: DXMT cannot race where a native driver can.
visual visual.isolated.c:25933
